# 示例代码开发规范指南

本指南旨在统一 `mcpstore` 项目中示例代码的编写风格和输出格式。所有新增或修改的示例代码都**必须**严格遵守以下规范。

## 1. 核心原则 (Core Principles)

1.  **无函数封装**：示例代码应为直观的脚本形式，**严禁**在示例文件中定义任何辅助函数或包装函数。所有演示逻辑直接在顶层按步骤顺序编写（公共工具逻辑可集中在 `example_utils.py` 等工具模块中）。
2.  **结构化输出**：使用统一的树形结构 (`├─`, `│`, `└─`) 进行日志输出，确保视觉上的整洁和层级清晰。
3.  **标准流程头尾**：除了极特殊的单一功能演示外，所有完整示例必须包含标准的**初始化与清理**流程。
4.  **环境导入**：代码首行必须导入并执行 `setup_example_import`，以确保使用本地开发版本的 `mcpstore`。
5.  **英文输出**：示例代码中的注释和打印信息（`print` 文本）统一使用**英文**，确保国际化通用性（本指南使用中文说明，但代码模板和实际示例输出以英文为准）。

## 2. 标准代码结构 (Standard Code Structure)

每一个示例文件都应遵循以下骨架结构：

### 2.1 头部导入与初始化
```python
from example_utils import setup_example_import

setup_example_import()
from mcpstore import MCPStore

# ============================================================
# [Example Name] - [Short Description]
# ============================================================

print("\n" + "=" * 60)
print("  MCPStore Standard Workflow Example")
print("=" * 60)
```

### 2.2 必须包含的起始步骤 (Step 1-2)
任何操作开始前，必须先初始化并完成一次配置清理（包含清理前后对比）。

```python
# ------------------------------------------------------------
# Step 1: Initialize MCPStore
# ------------------------------------------------------------
print("\n[Step 1] Initialize MCPStore")
store = MCPStore.setup_store(debug=False)
print("  └─ ✓ MCPStore instance created successfully")

# ------------------------------------------------------------
# Step 2: Reset Configuration (Show Before/After)
# ------------------------------------------------------------
print("\n[Step 2] Reset Configuration (Show Before/After)")
config_before_reset = store.for_store().show_config()
store.for_store().reset_config()
config_after_reset = store.for_store().show_config()
print("  ├─ Config before reset =>")
print(config_before_reset)
print("  ├─ Config after reset  =>")
print(config_after_reset)
print("  └─ ✓ Configuration reset and shown (before/after)")
```

### 2.3 必须包含的结束步骤 (Step N)
操作结束后，显示最终状态并再次清洗环境（包含清理前后对比）。

```python
# ------------------------------------------------------------
# Step [N]: Reset Configuration (Final Cleanup - Show Before/After)
# ------------------------------------------------------------
print("\n[Step [N]] Reset Configuration (Final Cleanup - Show Before/After)")
config_before_final_reset = store.for_store().show_config()
store.for_store().reset_config()
config_after_final_reset = store.for_store().show_config()
print("  ├─ Config before final reset =>")
print(config_before_final_reset)
print("  ├─ Config after final reset  =>")
print(config_after_final_reset)
print("  └─ ✓ Configuration reset and shown (before/after)")

# ============================================================
print("\n" + "=" * 60)
print("  Standard Workflow Completed")
print("=" * 60)
print()
```

## 3. 常用方法标准输出规范 (Standard Output Snippets)

所有涉及以下方法的调用，必须使用完全一致的代码块进行输出。

### 3.1 添加服务 (Add Service)
```python
# ------------------------------------------------------------
# Step X: Add MCP Service
# ------------------------------------------------------------
print("\n[Step X] Add MCP Service")
# ... 定义配置 ...
store.for_store().add_service(service_config)
print(f"  ├─ Service Name: {service_name}")
print(f"  ├─ Agent Name: {agent_name}")
print("  └─ ✓ Service added successfully")

# ------------------------------------------------------------
# Step X.5: Show Configuration After Add Service (Compare with After Reset)
# ------------------------------------------------------------
print("\n[Step X.5] Show Configuration After Add Service (Compare with After Reset)")
config_after_add_service = store.for_store().show_config()
print("  ├─ Config after reset (from Step 2) =>")
print(config_after_reset)
print("  ├─ Config after add service        =>")
print(config_after_add_service)
print("  └─ ✓ Configuration comparison shown (reset vs add service)")
```

**注意**：`config_after_reset` 变量来自 Step 2，需要在同一脚本中保持可用。

### 3.2 等待服务就绪 (Wait Service)
```python
# ------------------------------------------------------------
# Step X: Wait for Service Ready
# ------------------------------------------------------------
print("\n[Step X] Wait for Service Ready")
store.for_store().wait_service(service_name)
print(f"  ├─ Service Name: {service_name}")
print("  └─ ✓ Service is ready")
```

### 3.3 列出所有服务 (List All Services) - **严格执行**
```python
# ------------------------------------------------------------
# Step X: List All Services
# ------------------------------------------------------------
print("\n[Step X] List All Services")
services = store.for_store().list_services()
print(f"  ├─ Total Services: {len(services)}")
for idx, service in enumerate(services, 1):
    svc_name = service.name
    svc_status = str(service.status).split(".")[-1].replace("'", "")
    svc_transport = service.transport_type
    svc_transport_str = str(svc_transport).split(".")[-1].replace("'", "") if svc_transport else None
    svc_client_id = service.client_id
    svc_config = service.config if service.config else (service.state_metadata.service_config if service.state_metadata else None)
    svc_tools = service.tool_count
    print(f"  ├─ [{idx}] {svc_name}")
    print(f"  │   ├─ Status: {svc_status}")
    if svc_transport_str:
        print(f"  │   ├─ Transport: {svc_transport_str}")
    # Show URL for HTTP transport, Command/Args for STDIO transport
    if svc_transport_str == "streamable_http" and service.url:
        print(f"  │   ├─ URL: {service.url}")
    elif svc_transport_str == "stdio":
        if service.command:
            print(f"  │   ├─ Command: {service.command}")
        if service.args:
            print(f"  │   ├─ Args: {service.args}")
    if svc_client_id:
        print(f"  │   ├─ Client ID: {svc_client_id}")
    if svc_config:
        print(f"  │   ├─ Config: {svc_config}")
    print(f"  │   └─ Tools: {svc_tools}")
print("  └─ ✓ Service list retrieved successfully")
```

**注意**：
- `list_services()` 返回的是 `ServiceInfo` Pydantic 对象列表，使用属性访问（如 `service.name`），而非字典访问（如 `service["name"]`）。
- `status` 和 `transport_type` 是枚举类型，需要转换为字符串显示。
- **不同传输模式的展示差异**：
  - **HTTP 模式** (`transport_type=STREAMABLE_HTTP`)：显示 `URL` 字段（如 `http://127.0.0.1:8011/mcp`）
  - **STDIO 模式** (`transport_type=STDIO`)：显示 `Command` 和 `Args` 字段（如 `command='python'`, `args=['/path/to/script.py']`），此时 `url` 为空字符串
  - 两种模式都会显示完整的 `Config` 字典，但内容结构不同

#### 3.3.1 不同传输模式的 ServiceInfo 示例对比

**HTTP 模式示例**（`transport_type=STREAMABLE_HTTP`）：
```python
ServiceInfo(
    url='http://127.0.0.1:8011/mcp',
    name='mcpstore',
    transport_type=<TransportType.STREAMABLE_HTTP: 'streamable_http'>,
    status=<ServiceConnectionState.HEALTHY: 'healthy'>,
    tool_count=2,
    config={'url': 'http://127.0.0.1:8011/mcp'},
    command=None,
    args=None,
    ...
)
```

**STDIO 模式示例**（`transport_type=STDIO`，Studio 模式）：
```python
ServiceInfo(
    url='',  # 空字符串
    name='mcpstore-wiki',
    transport_type=<TransportType.STDIO: 'stdio'>,
    status=<ServiceConnectionState.HEALTHY: 'healthy'>,
    tool_count=3,
    config={'command': 'python', 'args': ['/path/to/script.py'], 'env': {}},
    command='python',
    args=['/home/yuuu/app/2025/2025_6/mcpstore/wiki/mcp_service_wiki_studio.py'],
    env={},
    ...
)
```

**关键差异**：
- HTTP 模式：`url` 有值，`command`/`args` 为 `None`
- STDIO 模式：`url` 为空字符串，`command`/`args` 有值，`config` 包含 `command`/`args`/`env`

### 3.4 列出所有工具 (List All Tools) - **严格执行**
```python
# ------------------------------------------------------------
# Step X: List All Tools
# ------------------------------------------------------------
print("\n[Step X] List All Tools")
tools = store.for_store().list_tools()
print(f"  ├─ Total Tools: {len(tools)}")
for idx, tool in enumerate(tools, 1):
    tool_name = tool.name
    tool_desc = tool.description
    tool_desc_display = tool_desc[:80] + "..." if len(tool_desc) > 80 else tool_desc
    tool_service = tool.service_name
    tool_input_schema = tool.inputSchema
    tool_required_params = tool_input_schema.get("required", []) if isinstance(tool_input_schema, dict) else []
    print(f"  ├─ [{idx}] {tool_name}")
    print(f"  │   ├─ Service: {tool_service}")
    if tool_required_params:
        print(f"  │   ├─ Required Params: {tool_required_params}")
    print(f"  │   └─ Description: {tool_desc_display}")
print("  └─ ✓ Tool list retrieved successfully")
```

**注意**：
- `list_tools()` 返回的是 `ToolInfo` Pydantic 对象列表，使用属性访问（如 `tool.name`）。
- `inputSchema` 字段包含 JSON Schema 格式的参数定义，可用于了解工具调用所需的参数。

#### 3.4.1 ToolInfo 标准结构示例

```python
ToolInfo(
    name='mcpstore_wiki_byagent_demo_agent_http_get_current_weather',
    tool_original_name='mcpstore_wiki_byagent_demo_agent_http_get_current_weather',
    service_original_name='mcpstore',
    service_global_name='mcpstore',
    service_name='mcpstore',
    description='Get current weather information for specified city, including temperature and weather conditions',
    client_id='client_global_agent_store_mcpstore',
    inputSchema={
        'properties': {
            'query': {'title': 'Query'}
        },
        'required': ['query'],
        'type': 'object'
    }
)
```

**字段说明**：
- `name`: 工具的唯一标识名称（可能包含 agent 前缀）
- `tool_original_name`: 工具的原始名称（不含 agent 前缀）
- `service_name`: 工具所属的服务名称
- `service_original_name`: 服务的原始名称
- `service_global_name`: 服务的全局名称
- `description`: 工具的功能描述
- `client_id`: 关联的客户端 ID
- `inputSchema`: JSON Schema 格式的参数定义，包含 `properties`（参数属性）、`required`（必需参数列表）、`type`（对象类型）等

### 3.5 调用工具 (Call Tool) - **严格执行**
```python
# ------------------------------------------------------------
# Step X: Call Tool
# ------------------------------------------------------------
print("\n[Step X] Call Tool")
# ... 定义调用参数 ...
tool_result = store.for_store().call_tool(tool_name, tool_params)
print(f"  ├─ Tool: {tool_name}")
print(f"  ├─ Parameters: {tool_params}")
is_error = tool_result.is_error
content = tool_result.content
print(f"  ├─ Is Error: {is_error}")
print(f"  ├─ Content Items: {len(content)}")
for idx, item in enumerate(content, 1):
    item_type = item.type
    item_text = item.text
    item_text_display = item_text[:100] + "..." if len(item_text) > 100 else item_text
    print(f"  ├─ [{idx}] Type: {item_type}")
    print(f"  │   └─ Text: {item_text_display}")
if tool_result.data:
    print(f"  ├─ Data: {tool_result.data}")
print("  └─ ✓ Tool called successfully")
```

**注意**：
- `call_tool()` 返回的是 `CallToolResult` 对象，使用属性访问（如 `tool_result.is_error`），而非字典访问。
- `content` 是 `TextContent` 对象列表，每个对象有 `type`、`text`、`annotations`、`meta` 属性。
- `text` 字段可能很长，建议限制显示长度（如 100 字符）并添加省略号。

#### 3.5.1 CallToolResult 标准结构示例

```python
CallToolResult(
    content=[
        TextContent(
            type='text',
            text='{"content":[{"type":"text","text":"https://doc.mcpstore.wiki/",...}],...}',
            annotations=None,
            meta=None
        )
    ],
    structured_content={
        'content': [...],
        'structured_content': {'result': 'https://doc.mcpstore.wiki/'},
        'data': 'https://doc.mcpstore.wiki/',
        'is_error': False
    },
    data={
        'content': [...],
        'structured_content': {'result': 'https://doc.mcpstore.wiki/'},
        'data': 'https://doc.mcpstore.wiki/',
        'is_error': False
    },
    is_error=False
)
```

**字段说明**：
- `content`: `TextContent` 对象列表，包含工具返回的文本内容
- `structured_content`: 字典格式的结构化内容
- `data`: 字典格式的数据，通常包含提取后的结果
- `is_error`: 布尔值，表示调用是否出错
